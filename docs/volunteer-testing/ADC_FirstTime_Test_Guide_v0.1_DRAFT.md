# AD&C はじめての構築・検証ガイド（第三者テスト用）

- 版：v0.1 / Draft（2026-10-18）
- 対象：AD&Cを初めて試す知人。専門用語やGitHubの操作知識は不要。
- 目的：**AIへの簡単な指示だけでKB（知識ベース）が作成され、あとで実際に使える形で受け取れるか**を確認する。
- 所要時間：環境によって異なる。時間切れ・利用制限も有効な検証結果なので、無理に完走しなくてよい。

> **お願い**：実名、メール、住所、勤務先の資料、顧客情報、パスワードなどは入れないでください。まずは新しい空の保存先と架空の情報で試してください。既存ファイルの削除、公開共有、課金、アクセス権変更は不要です。

**このガイドと検証指示文はGitHubで個別に読めます。ZIP一式をダウンロードする必要はありません。** 初期構築後の検査には[構築後テスト・レポート生成指示文](ADC_PostInstall_Test_Prompt_v0.1_DRAFT.md)を使います。検証に協力することは任意です。

## 準備するもの

- 普段使うAIのチャット（ChatGPT / Claude / Gemini / Grokなど）。**新しい会話**を推奨。使用したサービス名・無料／有料の別は、あとで報告できれば十分。
- 保存先を1つだけ：端末の「ファイル」などのローカル保存、Google Drive、OneDriveなど。**公開用に変更しない**。
- **[AD&Cインストーラー（現行・単一版／Markdown）](../AgentOS-C_設計・構築運用指示書_一般配布版.md)を1つ**。AIの種類・無料／有料で選び分けない。AIが実際の保存先への読書き可否を確認し、クラウド連携／ローカル手動保存へ分岐する。旧「AI無課金ユーザー版」は過去の検証資料として残るが、今回の新規導入試験では使用しない。

GitHubの画面で中身を読むだけでなく、**そのMarkdownファイルをダウンロードしてAIに添付**してください。添付できないAIでは、本文の貼付を試しても構いません。その場合は「添付できず本文貼付」と報告します。リンクを示しただけでAIがファイルを読めたとみなさないでください。

## 実施手順（ここだけ読めば進められます）

1. AIの新しいチャットへ、インストーラーMarkdownを添付する。添付したら、次の一言だけ送る。

   ```text
   実行
   ```

2. **保存先だけを聞かれるか**を確認し、選んだ保存先を答える。AIが実際に直接読み書きできるかを調べ、方式に合わせて次の案内を出すはず。初手から大量の質問や長い設計議論が始まった場合は、そのまま記録し、無理に修正しない。
3. AIが「こういうKBを作る」という**推奨案を1案**示したら、内容と保存先を軽く見て、問題がなければ次を送る。

   ```text
   進めて
   ```

   ※外部公開、既存の重要ファイルの上書き、購入等を求められた場合は承認せず、検証を止めて構わない。

4. AIの完了報告を待つ。**説明文だけでなく、実際のファイル／ZIP／復元可能な全文テキストを受け取れたか**を確認する。保存先へ直接書けないAIでは、AIの案内に従って自分で保存する。受け取れないリンクは無理に繰り返さず、その状況を記録する。
5. 次に、GitHubの **[構築後テスト・レポート生成指示文](ADC_PostInstall_Test_Prompt_v0.1_DRAFT.md)** を取得して同じAIチャットに添付し、次だけ送る。

   ```text
   添付した検証指示文に従って、今のKBをテストして、レポートをMarkdownで作ってください。
   ```

6. AIが提出した検証レポートを受け取る。**必ずしも全項目PASSでなくてよい**。そのまま実態を報告してもらうことが大切。

## できたKBを人間が確認する3項目

AIのレポートと**別に**、分かる範囲で次を目視確認してください。

| 質問 | 記録例 |
|---|---|
| A. `実行` の後、まず保存先を尋ねた？ | はい／いいえ／判断できない |
| B. 本物のファイルを取得し、端末または自分の保存先で開けた？ | 開けた／取得できない／未実施 |
| C. 保存したKBに `START_HERE.md`、`BUILD_PLAN.md`、`00_system/registry.json` 相当がある？ | 確認した／一部だけ／未確認 |

**補足**：無料・制限環境ではZIPが作れなくても、各ファイルの相対パスと**本文全文**を持つ単一Markdown/TXTなら代替できます。別チャットからの自動読取・更新は必須条件ではありません。逆に「作りました」というAIの言葉だけでは、ファイル保存成功とは言えません。

## 開発者へのフィードバック（任意・1分）

レポートのほかに、次の3点が分かると助かります。記入しなくても構いません。

- **一番困った箇所**：例「AIが保存先を聞かなかった」「ファイルが開けなかった」「何をすればよいか分からなかった」
- **一番役に立ったこと**：例「何も知らなくてもフォルダと説明書ができた」
- **体験全体**：続けて使ってみたい／今は難しい／まだ判断できない

検証レポートやKB本体には、個人情報や非公開の保存先URLが入る可能性があります。**開発者へ共有する前に、必ずその内容を見て、共有してよい部分だけを渡してください。KB本体やチャット全文を送る必要はありません。**

## 困ったとき

- AIがファイルを読めない：添付機能や利用制限を確認。本文貼付でも不可なら **NOT_RUN** と記録し終了。
- 保存先へ書けない：不具合と決めつけず、ZIP／単一テキストによる受渡し方式に切り替えられるか確認。
- 完成ファイルを開けない：AIの「保存済み」とは区別し、**受取失敗**として記録。
- 同じ質問や操作が繰り返される：頑張って解決し続ける必要はない。そこで止めた結果が改善資料になる。

**検証用の指示文は、インストーラーではありません。初期構築が終わった後に別途渡してください。**
