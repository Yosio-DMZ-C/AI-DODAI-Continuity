# AD&C 導入済みKBの更新｜1.5.8 → 1.6.0

## 目的と範囲
AI製品のメモリ／プロフィール／カスタム指示などの持続設定を**Playbook発見の補助**として任意利用する。メモリを正本とせず、専門Playbookと既存案件KBを必要な時に実取得する。本人・組織の私的データや既存メモリは無断で変更しない。

## 対象と保全
対象は正規の導入版が1.5.8と確定しているKB。その他の版・版不明は `UPDATE.md` のFROM→TOを先に照合する。既存 `START_HERE.md`／`BUILD_PLAN.md`／`registry.json`／NodeID／fileId／Context／Playbook／定期タスク／共有設定はそのまま保持。新規Task・Draft・台帳、全体再構築、自動メモリ書換えは行わない。

## 適用手順
1. 本人の明示「アップデートして」等を受けたときだけ、[更新正本](UPDATE.md)を実取得し、連続した差分経路、保存権限、変更前の対象実体を確認する。
2. [1.6.0共通インストーラー](../AgentOS-C_設計・構築運用指示書_一般配布版.md)冒頭の「AIの記憶・プロフィール・持続指示への最小案内」を参照する。メモリが存在し本人が希望したときだけ公開の短文を登録候補として案内。メモリがない場合は既存の `START_HERE.md` と公開共有KBの軽量索引を使う。
3. 本人がメモリを設定したと述べても、実呼出し未確認なら「利用成功」とはしない。メモリ内の古い情報と現行KBが異なる場合はKBを優先。初回構築は再実行しない。
4. 保存経路が使える場合のみ `START_HERE.md` の `ADNC_INSTALLER_VERSION` を1.6.0に更新し、必要なregistryの該当レコードのみ整合。保存後に対象実体を独立再取得し版到達を確認する。不可なら当該更新のみNOT_RUNとする。

## 検収と復旧
短文に個人情報・社内機密・個別JOB_IDが入らない。初回の保存先選択→接続→推奨案→本人の`進めて`を維持。実際のメモリ登録・別AIによるPlaybook発見は独立した実測がある場合のみPASS、未実施はNOT_RUN。変更したKBは既存ストレージの版履歴から対象だけ復旧できる。登録しなかった場合は原則KB本文に変更なし。
