# AD&C update guide — 1.3.10 → 1.4.0

> **実行前品質ゲート：FROM=`1.3.10`、TO=`1.4.0`（インストーラー版、数値で厳密照合）**。現在の対象KBの実取得済み導入版が**ちょうど1.3.10**で、[UPDATE.md](UPDATE.md)の経路検査・差分表提示・本人承認が成立した場合のみ、この一区間を実行。違う版なら**適用禁止**。完了後のDrive読戻しとregistry整合PASSまで次の版へ進まない。
- 適用範囲: **AD&Cインストーラー版** `1.3.10` から `1.4.0`。KBスキーマ版、個別設計版、Knowledge revisionとは独立。
- 更新方式: 利用者の明示承認後だけ実行。既存KBの差分更新。初期化・再インストールを禁止。
- 安全境界: この公開ガイドは個人KBの全文やファイルIDをGitHubへ送る指示ではない。公開／権限変更／削除／課金／外部転送はしない。

## 前提の確認（更新前）
1. 利用者が指定した**現在のKBだけ**の `START_HERE.md`、`BUILD_PLAN.md`、`00_system/registry.json` を実取得。NodeID、正本fileId、既存内容と変更前hash/revisionを控える。
2. `START_HERE.md` に `ADNC_INSTALLER_VERSION` があれば採用し、他のファイルの記載と矛盾しないか確認。なければ実際に使ったインストーラーを `BUILD_PLAN.md`・導入履歴から特定する。**確定できない場合はNOT_RUNで停止し、1.3.10と推測しない**。
3. 現行版が **1.3.10** でない場合、他の版用手順を探すか停止。既に **1.4.0** で内容も整合していれば無変更で終了。
4. 変更予定の表（対象／変更点／維持するもの）を提示し、**「実行する」など明示承認**を得る。承認がなければ何も変更しない。

## 適用する最小差分
- `START_HERE.md` の先頭タイトル・メタデータの適切な直後に以下の短いブロックを**1回だけ**追加または局所置換する。既存JSONメタデータの内部・コードブロック内部を壊さない。

```md
ADNC_INSTALLER_VERSION: 1.4.0
ADNC_UPDATE_MANIFEST: https://raw.githubusercontent.com/Yosio-DMZ-C/AI-DODAI-Continuity/main/docs/updates/LATEST.json

**更新時の入口**：利用者から「アップデートして」と依頼されたときだけ上記の公開manifestを実取得し、このKBのADNC_INSTALLER_VERSIONと比較する。差分がある場合は変更内容を表で提示し、利用者の「実行する」を受けてから、manifestが指定する版別ガイドを実取得・照合して局所更新する。取得不能・適用経路不明・競合なら無変更で停止。通常の質問で自動更新しない。
```

- `START_HERE.md` の**元のDrive fileId／NodeIDを維持**して更新。変更前の安全な履歴を既存 `90_history` またはDrive版履歴で保全し、元本文を消さない。
- `START_HERE` がregistryで管理される場合だけ、既存の同一レコードについてrevision、size/hash等の実際に採用しているフィールドを**再取得した内容に合わせて**更新する。登録のない場合は余計なダミーレコードを作らない。registryの保存前版も保全する。
- `BUILD_PLAN` が変更履歴を要求する場合だけ、更新実績を1行追記する。既存データは全面書換えしない。
- 知識、購入、嗜好、Gmail資料、履歴、その他の手順、共有設定、秘密情報には触れない。

## 実検収と停止
1. 実際のDriveから `START_HERE`、必要ならregistry/BUILD_PLANを再取得し、元のID・追加ブロック・本文保全・参照整合・hash/revisionを確認。
2. **全部の対象検査がPASSになった場合だけ** `ADNC_INSTALLER_VERSION=1.4.0` を確定状態として報告。途中失敗なら整合を優先して復元・保留し、PASSと報告しない。
3. 実施件数と結果を `PASS / FAIL / NOT_RUN` で短く表示。別チャットの生成、全アカウント探索、GitHubへの個人データ投稿は要求しない。

## 次回以降
- `アップデートして` → `START_HERE` の `ADNC_INSTALLER_VERSION` → 公開 `LATEST.json` 取得 → 版別の差分表 → 利用者承認 → 版別ガイド取得 → 更新＋読戻し。
- manifest内に現在版から最新版への**連続した適用経路**がなければ無理に飛ばさず停止。ファイル名・最新版だけを理由に旧版を上書きしない。
