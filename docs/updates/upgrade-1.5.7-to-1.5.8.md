# AD&C 差分手順｜1.5.7 → 1.5.8

> **FROM=`1.5.7`、TO=`1.5.8`**。必ず[UPDATE.md](UPDATE.md)先頭のFROM→TO連続版照合・差分表・本人による当該KB更新承認・保存後読戻しを適用する。導入版不明なら[ADOPT_LEGACY.md](ADOPT_LEGACY.md)へ進み、版数を推定しない。

## 目的

組織共有領域での業務・管理データは、その**対象組織の現行正式標準・権限・個別業務手順**をAD&C一般手順より優先する。複数組織の固定優先順位は作らない。個人KBの私的作業には無条件で組織規程を適用しない。

データを組織へ**入れる**ときは、元のデータ所有者・提供元の利用／提供許可と、**受入組織の正式標準・分類・ACL・用途・形式／出典・保持条件**を確認する。組織から**出す**ときは、元組織の持出・第三者送信許可と**受入側の許可・用途・保管条件**を確認する。組織A→B、組織→個人クラウド、組織→外部AIも境界移動に含める。契約、組織規程、法令、実サービスの権限はこの手順で迂回できない。

## 対象限定の差分

| 対象 | 必要な変更 | 保全するもの |
|---|---|---|
| `START_HERE.md` | この更新区間を実際に検収してから`ADNC_INSTALLER_VERSION: 1.5.8`へ更新 | NodeID、fileId、導入履歴、UPDATE入口、本人の採用済み条件 |
| 個人／組織の既存Contextや適用規則 | 既に「組織内も個人ルールが常に上位」「受入側だけの許可で第三者提供可」等の**実在する矛盾**があれば、その箇所のみ組織境界条件へ整合 | 正式な組織規程、業務固有の厳しい安全手順、現行の個人向け標準、無関係な内容 |
| メタデータとregistry | 更新対象がある場合のみowner／scope／sensitivity／sharing_scope／sources／approval_state等の既存項目・参照・hash/revisionを整合 | 既存ID、所有者、fileId、ACL、未取得の承認状態 |
| 組織データ・送受信・公開先 | **この版更新では一切自動搬送しない**。必要な正式規程・実権限が揃う個別案件だけ後日別工程で検証 | 組織データ、機密情報、第三者の権利、既存の共有設定 |

## 適用・検収

1. 対象KBの`START_HERE.md`から実際に`ADNC_INSTALLER_VERSION: 1.5.7`を取得し、取得時の[LATEST.json](LATEST.json)で`1.5.7→1.5.8`が連続した唯一の区間であることを確認する。版不明・異版の対象にこの一区間だけを強制適用しない。
2. 更新候補の実在する規則・Contextを必要部分だけ取得し、組織の**正式**標準がある場合はその版、適用範囲、管理者、実共有ACLを取得できた範囲で照合。規程を取得できなければ、組織に関わる移動は未許可・`NOT_RUN`とし、AD&C一般規則から承認を推定しない。
3. [UPDATE.md](UPDATE.md)の差分表と、本人による対象KBへの更新承認がある場合のみ、既存fileIdと競合状態を再確認して必要な箇所を局所修正する。**既存規則に該当する矛盾が無ければ本文・組織データ・ACL・秘書タスクは変更不要**。全件の分類・組織別新KB・新台帳を作らない。
4. 変更したファイルとregistryのID／version／hash・差分／保持対象を実読戻しする。更新規則が明示され、必要な差分・保持条件がPASSした場合だけ対象KBの導入版を`1.5.8`へ変更し、再取得して確定する。
5. `PASS / FAIL / NOT_RUN`は**KBの更新／組織規程の取得／本番の組織間移動**をそれぞれ別判定。版更新PASSを組織間共有・第三者送信・外部AI連携の実許可と読み替えない。未完了の個別境界案件は対象だけ未実行として既存案件に残す。

既存の`1.5.6→1.5.7`以前の更新履歴・本人の採用済み制作方式・正本・NodeID・共有設定は保持する。この更新に伴う再インストール、無関係な旧KBの一括編集、公開・課金・権限変更・外部送信は行わない。
