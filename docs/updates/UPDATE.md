# AD&C｜既存KBのアップデート実行正本

> **品質ゲート（先に判定し、満たさなければ更新禁止）**
>
> 1. **FROM** = 対象KBの`START_HERE.md`から実取得した **ADNC_INSTALLER_VERSION** の数値 `X.Y.Z`。未記録なら実導入履歴から確認し、推定しない。
> 2. **TO** = [LATEST.json](LATEST.json)の`track=installer`かつ`product=AD&C`の`latest_version`を**今回実取得した時点で数値として固定**したもの。現時点の例は **1.5.1**。例示値を根拠にせず毎回実取得する。
> 3. `FROM=TO`なら**無変更で終了**。`FROM>TO`なら安全停止。`FROM<TO`ならmanifest内の`from_version→to_version`を**FROMからTOまで途切れず、重複・循環なしで連結**できる場合だけ更新候補とする。**途中の1版でも欠ければNOT_RUN・変更禁止**。
> 4. **版別の手順書を1件ずつ実取得し、各文書冒頭のFROM/TOがmanifestの区間と完全一致**することを確認する。タイトルやファイル名だけで同一と判断しない。リンク不通・不一致・現在版不明・同一ID競合時はSTOP。
> 5. **すべての変更を一覧表（適用順・FROM→TO・対象・内容・維持対象）で提示し、利用者が実行を承認するまで書き込まない**。個別区間の実施後はDrive原本を読戻し、版・ID・本文・registryの整合がPASSの場合だけ次区間へ進む。途中FAILなら復元または保留し、成功した区間と未実施区間を分ける。
>
> **完了ゲート**：承認した固定目標`TO`まで全区間の検収PASS、対象KBの実読戻しで`ADNC_INSTALLER_VERSION=TO`を確認したときだけ「最新版への更新完了」。途中まで通過した場合はその到達版・残りを明示し、TOに達したことにはしない。

## 起動と範囲

- 起動語：本人による「アップデートして」等の**明示指示**。秘書による日次バージョン確認は読取・通知のみであり、自動実行の承認ではない。
- インストーラー版（製品が配布されたルールの版）を比較する。KB設計版、registryのschema_version、Knowledgeのrevisionは別物であり、更新する範囲に含めない。
- 対象は本人が指定した**現在のKBだけ**。Driveアカウントを跨がず、私的なNodeIDやリンク、データ本文を公開GitHubへ送信しない。
- 初回導入・再インストール禁止。NodeID・元Drive fileId・所有者・共有設定・既存知識・原本履歴を維持する。公開、削除、権限変更、外部送信、課金は別の明示承認なしに実行しない。

## 実行手順（品質ゲート通過後）

1. `START_HERE.md`、必要な`BUILD_PLAN.md`・`registry.json`を実取得し、導入版と対象ID・変更前revision/hashを控える。導入版がなく根拠に欠ける場合、勝手に推定しない。
2. `LATEST.json`を実取得・JSONとして検証し、今回の`TO`（例ではなく**取得した正確な番号**）をロック。後からGitHubで新しい更新が公開されても、この実行中の目標を自動変更しない。
3. 経路の各区間の`instruction_url`が、このリポジトリの`docs/updates/upgrade-*`を指すことと、版別手順の冒頭FROM/TO値がmanifestと一致することを確認。候補ごとの差分を1つの表でまとめる。
4. その表を利用者に提示して実行承認を得る。**承認前は読取以外行わない。**
5. 各区間で、対象だけの旧版を保全 → 版別手順に従い既存fileIdのまま差分更新 → 必要なregistry/hash/revision同期 → Driveから実再取得しPASS/FAIL/NOT_RUN判定。**区間の検収PASSが済むまで次区間へ進まない。**
6. 完了ゲート後、`FROM→TO`、保存・読戻し結果、残存NOT_RUNを簡潔に報告。入力が古い・読めない・更新不能な場合は別KBで代行したと偽らず停止する。

## 版別手順の契約

各`upgrade-A-to-B.md`の**冒頭**は必ず`FROM=A`、`TO=B`を数値で宣言する。AIは実行直前に現在KBがAであることを再確認し、Bへの一区間だけを行う。版別手順は**具体的な差分**だけを担い、上記の共通安全ゲートを重複して長文化しない。

日次の**更新通知**の品質条件は秘書の現行指示に従い、`X.Y`上昇時だけ一度知らせる。`X.Y.Z`のZだけ変化したときは通知しないが、利用者が自発的にアップデートを求めれば、Zも含めた全区間を確認できる。
