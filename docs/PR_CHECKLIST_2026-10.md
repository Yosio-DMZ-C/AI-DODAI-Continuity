## 実証の開示基準

完全にPASSしていない機能を「導入できる」と保証しない。AIが「完了」と報告しても、実物の存在・JSON・参照・ファイル形式を独立確認する。未実施項目はNOT_RUNと記載する。

## PR投稿文の方向性（編集用）

**軸：** 「AIを乗り換えても、自分の知識は残る。」

**補足：** AgentOS-Cは新しいAIではなく、自分の情報をAIの外で管理し、必要時に引き継ぐための仕組み。無料・制限環境でも最小限のKB構築とバックアップを狙い、AIによる受渡しの実動作を公開検証中。成功も失敗も隠さず記録していく。

**誘導先：** GitHub README → `docs/wiki/Home.md` → Quick Start → 設計書。

## 人間・AI共同レビューの表示ルール

**正式な共通基準：** [開発調査・プロジェクト推進の共通標準 §6.2](PROJECT_EXECUTION_STANDARD.md)。このPRだけでなく、設計・調査・実装・資料作成の共同作業全体に適用する。

| 必ずレンダリング表示する固定タグ | 確認内容 |
|---|---|
| `【人間確認】` | 表示・内容・実用性が意図どおりかを利用者が確認 |
| `【人間判断】` | 採否・公開・優先度等を利用者が決定 |
| `【AI検査】` | AIが実ファイル・リンク・参照・内容を検査。PASS/FAIL/NOT_RUNは別記 |
| `【未検証】` | 未実施や証拠不足の理由、担当、次の検証 |

- レビュー依頼には **固定タグ + レンダリング済み直接リンク + 見る箇所 + 確認観点 + 返答方法** を必ず示す。
- 人間はソースやPR差分を読む必要はない。レビュー用のタグは原則として正式公開文章には残さない。
- 「確認OK」「修正：対象と内容」「採用／保留」で返答できるようにする。
