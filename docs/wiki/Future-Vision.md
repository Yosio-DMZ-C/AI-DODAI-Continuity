# 将来構想 — 個人から組織・共有知へ

[概要へ戻る](Home.md) | [実証状況](Verified-Results.md)

> **以下は将来構想であり、現時点で一括導入できる完成済み機能ではありません。** Foundationの構築・保存・再開・更新の実証を優先します。

## 1. 組織標準KB（Organization Standards KB）

企業・NPO・公共団体などが保有する規程、制度、標準作業手順、書式、記入例を元に生成するKBです。

**狙い：** 利用者が実際に仕事をするとき、AIが適用される規程と書式を提示し、記入・確認を支援することで、記憶に頼る運用と「資料配布中心の制度説明研修」への依存を減らすこと。

- **個人モード（既定）：** 組織標準KBの判定や検索を行わず、処理を軽くする。
- **組織モード（明示的に有効化）：** 権限内でアクセスでき、当該業務に適用される**現行の組織内規程**を一般的なCommunityの助言より優先する。
- **例外・矛盾：** AIが独断で規程を改変せず、原文と版を示して、組織が指定する所管者・既存の報告ルートへ疑義をエスカレーションする。
- **強制力：** 技術的な遵守強制は前提にしない。現行の「人の記憶頼り」より利用時の発見・案内を改善する。
- **境界：** 法令等で受講記録が必要な研修や、実技訓練、権限者の最終承認を一律に代替するものではない。

組織文書が改訂されたときの追従性と、閲覧権限・機密性の維持が実装上の重要課題です。

## 2. インストーラKB（Installer KB）

AgentOS-Cの**環境構築支援**と、組織の**標準文書から標準KBを構築する支援**を行う、対話型の知識・手順群です。プログラムとしての完全自動インストーラは初期必須条件としません。

- AI環境と保存先の実能力を調べる。
- 構築案を1つ提示し、必要な承認・設定操作のみ利用者に依頼する。
- 許可された規程・書式・記入例を整理し、適用条件・例外・出典・版を維持して標準KBへ変換する。
- 実ファイルと参照を検査し、欠落・矛盾や所管不明を利用者へ確認する。
- 接続やエスカレーションは既存のGoogle Drive、SharePoint、GitHub Issues等のサービスを活用し、新たな問題管理システムを作らない。

**Installer KBと組織標準KBは別物**です。前者は構築・設定・検査の方法、後者は実務で参照する規程・制度の内容です。

## 3. 共有知（Community）

異なる主張、根拠、反論、適用条件、未解決事項を出典付きで整理し、調査コストを減らす構想です。組織の正式規程の代わりに一般論を適用するものではありません。

[AgentOS-C Shared Knowledge](https://github.com/Yosio-DMZ-C/AgentOS-C-Shared-Knowledge)

## 4. Core Life Skills

子育て、医療の相談準備、契約、防災など、重要な判断時に初動・確認・記録を補助する任意のSkill群です。組織標準KBとは別機能で、[ロードマップ](https://github.com/Yosio-DMZ-C/AgentOS-C/blob/main/docs/CORE_LIFE_SKILLS.md)は設計段階です。

## 実装の順序

**Foundationの実動作検証 → Installer KBの小さな試作 → 架空の旅費規程と申請書を用いた組織標準KB試験 → 運用・権限・更新の検証。**

個人KBと組織KBを無断で混在させず、個人情報・非公開文書を公開リポジトリへ転記しない方針は共通です。
