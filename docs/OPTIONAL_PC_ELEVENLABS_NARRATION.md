## 使う条件

1. ユーザーが**明示的にAIナレーション生成を選択**し、ElevenLabsの契約・利用権・クレジット・対応する実行環境を持つ。
2. 有料クレジット消費／APIへの原稿送信／音声生成範囲を事前に提示し、本人の承認を得る。秘密のAPIキー・トークンをチャットやGitに書かない。
3. 音声ツールや採用Voice ID／モデル／台本との一致を**実取得して検査**。他の章・旧台本用のMP3を「近いから」と流用しない。
4. 対応PC・スクリプトが使えない場合は標準の本人録音方式に戻す。特定のPCやサービスの取得・導入を利用者へ強制しない。

## 既存実例：第1作 ElevenLabs音声生成・共有 Runbook v0.9（2026-10-22）

この履歴手順は**第1作スライド01〜15のAI音声**をWindowsから生成するために設計された特例であり、すべての利用者や日次クリップに適用しない。**本人が読む第16枚のENDINGは対象外**。制作パッケージが実在し、許可と実行環境がある場合の実操作は次のとおり。

1. 配布ZIPを入手し、信頼できる配布元と同梱内容を確認。Windowsの「ブロックの解除」が必要と表示された場合は出所を確認して判断し、企業ポリシーやSmartScreenを回避しない。管理者ポリシーを変更しない。
2. ZIPを展開。旧試験パッケージでは入口は **`音声生成.cmd` の1件のみ**。内部には `_internal/ADNC_AudioEngine.ps1` と `_internal/Narration_01to15.zip` を置く。**起動BATやソースを再現できていない場合はNOT_RUN**。本Git文書だけでは実行パッケージを提供していない。
3. 初回に、最大15本のElevenLabsクレジット消費と送信範囲を説明し、承認されなければ生成しない。APIキーをチャット・Git・共有ZIPへ入れず、可能なら既存のOS保護付きストアから取得。
4. まず **01〜03の3本だけ生成・試聴**。ナレーション本文・言語・発音・速度・声の印象・破綻を確認。NGなら残り12本は作らず差分を修正。
5. ユーザーが続行を選んだ場合だけ残り04〜15を生成し、MP3と `MANIFEST.txt` を **`PleaseUPLOAD.zip`** にまとめる。原稿／Voice ID／モデル等が一致する既存MP3のみ再利用。CRC・SHA-256等で中身を検証してから送る。
6. 完成ZIPが同名で既にあるなら**無断上書きしない**。既存成果物を保全し、新規の正しい版として区別する。ユーザーが音声ZIPを制作チャットへ返し、AIがスライド／字幕／動画と同期する。
7. APIへの送信後にエラーが起きた場合、**再送による二重課金の可能性**があるため自動再試行しない。支払・実際の音声・字幕・動画の各検査は別々にPASS/FAIL/NOT_RUNを記録する。

### 実装・安全上の留意点

- 旧v0.9ではBATからそのプロセスのPowerShell実行ポリシーを指定したが、**PC全体や組織の実行ポリシー変更を推奨しない**。会社管理端末なら制限を尊重する。
- **元の第1作向けZIPや実際のWindows動作はGitの文書保存によって提供・再試験されたわけではない**。旧記録の状態は、配布パッケージと原稿の静的検査PASS／Windowsの実操作・ElevenLabs API課金と聴感NOT_RUN。
- 本人音声の無断送信、声クローン、なりすまし目的の音声変換は行わない。本人の同意なく外部のボイスチェンジャー等へ録音を渡さない。
- 第1作の仕様（15枚＋本人ENDING）を他の作品の規則として固定しない。
- AI音声方式を選んだ具体的な動画制作でも、実MP4へナレーションが**統合・デコードできるまで完成扱いしない**。2026-10-24 Muse実験当時のMP4は、AIナレーションを後工程で追加予定だったためナレーション未統合だった、という工程上の説明を用いる。

## 一般向け標準へ戻す方法

ElevenLabs未契約／PCなし／API未接続／支払い承認なし／音声が不自然、といったときは、**完成ナレーション原稿をチャットにそのまま全文表示**する。ユーザーがスマートフォン標準の録音機能などで読み上げて1ファイルを送れば、AIが音声を検査してスライド・字幕・映像を同期する。必要な人間操作を音声の録音・受渡し以外に増やさない。

**本手順は人間や検索から発見できるようGitに残す補助情報であり、AIが毎回読むべき常設実行正本ではない。**
