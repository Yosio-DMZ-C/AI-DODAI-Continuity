# WordPress画像登録・ページ公開の検収 Playbook v0.1.0 — Draft

- 状態：**Draft／限定実機1件**。正式Activeではない。対象：WordPressに正本画像を載せる作業。親手順：[共通実行標準](../PROJECT_EXECUTION_STANDARD.md)および[共有KB開発実務規則](https://github.com/Yosio-DMZ-C/AD-C-Shared-Knowledge/blob/main/docs/DEVELOPMENT_WORKFLOW_PRACTICES.md)。
- **自然言語の入口**：「手元の公式ロゴをWordPressの固定ページに掲載して、リンクを添えて公開して」「画像は見えているのにWordPressに置けないから、別の登録経路を試して」。
- 目的：**承認済みの元画像を改変・再生成せず**、WordPress上の画像URLとページに正しく保存し、公開／読戻しを事実として区別する。
- 入力：対象WordPressサイトとページ（新規／既存）、公式画像原本または会話内添付、本文・リンクと公開承認。出力：ページID・公開URL、画像メディアID・URL、検査結果。認証情報・非公開画像は無承認で外部公開しない。

## 作業順序

1. **実体と権限**：既存ページ・親・slug、元画像の所有・採用状態・サイズ、ユーザーの公開承認を確認。公式ロゴは生成画像で代用せず、装飾・配置・結合のみ許された範囲で行う。記事やインストール案内のURLは既存の正本README等を現時点で実取得して決める。記憶のURLを正本としない。
2. **登録経路A（公開直画像URL）**：サイト側のメディア登録機能にURLを渡し、**実際に画像のバイト列が得られるURL**であることを確認。クラウドの共有閲覧ページ・ダウンロード同意HTMLは画像URLとは限らない。画像のContent-Typeや実体が不明なら成功を主張しない。
3. **経路A失敗時のB（添付データ）**：利用中の連携に「会話に添付された画像をWordPressメディアへ登録する」機能があれば使う。添付ファイル識別子を使用し、成功応答からWordPressホストの実URL・メディアIDを得る。ローカルパスやチャット専用sandbox URLをWordPress本文に貼らない。**ChatGPT/WPWriterの一実例**では、クラウドURL取込が画像形式不正で失敗し、`upload_attached_images`で3点の個別画像登録に成功した（2026-11-03）。他AI、全添付、全プランで成功するとは限らない。
4. **登録後**：媒体一覧でID・URL・寸法・代替テキストを確認。既存ページは対象HTMLの一部だけを編集し、本文・前後の変更を最小化。ロゴを各該当セクションに置き、必要なら合同ロゴをアイキャッチにする。本文の画像リンクにはサイト内にホストされた実メディアURLを使う。
5. **リンク**：本体GitHub、`QUICKSTART.md`、詳しい導入ガイドなど、**正本の入口で実取得したリンク**を載せる。リンク先ごとの役割・現在のβ/制約を平易に説明。リンクだけ先行して未検証の効能を断言しない。
6. **検収**：保存後のページ本文を再取得し、期待する画像URL・alt・導入ガイド・slug・親設定を確認。メディア一覧に3点等必要個数があることを確認。公開は明示承認がある場合に実施し、公開ステータスと公開URLを再取得。Webからの実レンダリング確認・iPhoneでの「写真」に保存成功は**別判定**で、未実施ならNOT_RUN。
7. **失敗時の補修**：登録失敗 → メディア一覧で重複や実成功を先に確認 → 失敗原因を観測と推測に分離 → 経路を変更して一度だけ安全に再試行。ページ上書き失敗は既存本文を保存し、正本を維持。画像登録・本文保存・公開・外部表示・端末保存をまとめてPASSにしない。

## 2026-11-03 限定検収（匿名化）

- クラウド閲覧URLを`upload_media`に渡す：**FAIL**（ツールは画像形式ではないと返した）。**原因推測**：共有閲覧・ダウンロードURLが画像バイトではなくHTML等を返した可能性。応答Content-Typeの独立解析はNOT_RUN。
- 会話添付の画像IDを`upload_attached_images`で登録：**PASS（3画像のメディアIDとURLを取得）**。
- WordPress本文への画像3点、導入ガイドリンクの保存・再取得：**PASS**。ページ公開ステータス：**PASS（接続アプリの確認）**。
- 公開URLの外部ブラウザ描画、モバイル表示、画像表示の視覚検収：**NOT_RUN**（今回の外部アクセス経路では確認不可）。別AIコールドスタートQ2：**NOT_RUN**。人間の端末保存：**NOT_RUN**。
- 利用条件：WordPressへの権限ある接続と、元画像が会話添付としてアクセスできる環境。事前の無料画像生成枠は不要。画像生成枠と既存画像アップロードを混同しない。

## 開発リーダーへの連絡仕様

AD&C紹介文を書く依頼で都度URL探索に迷わないように、**公開READMEを単一入口**とし「GitHub本体」「3ステップ導入」「詳しい導入」「共通インストーラー」の役割と相互リンクを明示する。AI側はREADMEを取得してから提示し、古いAgentOS-C名や固定URL記憶で判断しない。リンクの取得・利用者画面での開通・導入成功は別々の判定とする。

Q1=本文に入口と実体あり（本Draftブランチのみ）；Q2=NOT_RUN；Q3=上記1件のWP実動作のみPASS；Q4=WordPress接続で公開状態確認PASS、外部閲覧NOT_RUN。Active昇格・main反映は既存審査に従う。
