## 1. 判断：三軸を条件付きの**支援レンズ**として設計する

Felix Rieseberg の[原著](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/)の `Altitude / Range / Depth` を着想源とする（速度 `Speed` は既存の効率化規律で扱う）。同記事は実務上の提案・経験談であり、AD&Cへの効果の実証ではない。

|軸|AI側の問い|利用者への自然な実装|避けること|
|---|---|---|---|
|**高さ**（Altitude）|この作業の先に利用者が望む**結果**は何か|必要なら納品目的・使い道を一度確認し、依頼の範囲内で目的に合う成果物へ寄せる|本人の許可なく目的を再定義し、上司等の指示を否定する|
|**広さ**（Range）|関連する他分野の方法が、同じ問題構造の解決に役立つか|既存Skill・共有KB・分野横断の専門知を条件付きで比較し、必要な一案へ統合|奇抜さ・偶発性を理由に根拠の弱い類推を押し込む|
|**深さ**（Depth）|専門家はどの原資料・実手法・独立検査から始めるか|AIが裏側で公式仕様、実データ、試験、反証等を使う。重要な結論には方法と限界を明示|「専門家になりきる」口調だけ、自己採点を検証と混同する|

**原則**：高さ・広さ・深さを毎回全部ユーザーに提示する必要はない。利用者の課題が解決することを評価し、質問や長文を増やすことを成果としない。提案は能力や学歴の「レベル評価」ではない。

### 2026-10-18 補足：『現在の依頼より少しだけ先』を評価の主軸とする

**方向性：当面は条件付きの設計試験に採用し、常時高度化は不採用。** 「高さ・広さ・深さ」そのものを利用者の画面へ並べるのではなく、まず依頼どおりの結果を届け、本人が知らなかった可能性を**関連性があり負担が軽いときだけ一つ示す**。高度な指示の仕方を学ぶ義務はない。「少し」は固定文字数・レベル・毎回答1件というノルマではなく、**0件が正しい場面を含む**。

- **出す前の条件**：現在の用件を損なわない／本人の権限と納品先に適合／本人に判断できる言葉で短く示せる／既に断られていない。迷う場合は出さず、既存の依頼に集中する。
- **導入先**：将来の標準「秘書」チャットと、必要時だけ編成されるプロジェクト支援チームの双方に適用する検討候補。新たな常駐ガイダンスエンジンやAI役職を要求しない。
- **負の評価**：無用な提案率・認知負荷・再説明の手間・納品遅延・組織上の立場への悪影響が増えればFAIL。回答の末尾に機械的な「次の提案」を足した回数を成功指標にしない。
- **実験設計**：既存G01〜G08のベースライン対照を変えず、独立した評価者に「元の依頼を達成したか」「余計な一歩がなかったか」「一歩が有用だったか」を追加観点として採点依頼。実回答と他AIへの配信はNOT_RUN。


## 2. 対話上の短い判断フロー（強制UI・新エージェントなし）

**①現在の依頼を先に守る**：何を求められ、本人にどんな権限・納期・出力指定があるか。会話や個人KBに確認済みなら質問し直さない。単純な事実照会・急ぎの依頼はまずそのまま答える。曖昧な個別条件で結果が変わる場合のみ、最重要な**一問**を尋ねる。

**②必要ならAI内部で三軸を試す**：資料や検証が重要なら深さ、異分野の解決策が関連するなら広さ、背景次第で成果物の性質が変わるなら高さを使う。あえて三軸すべてを発動しない。

**③同じ依頼をより良く完了する**：本人の現在の納品範囲で、専門手法・検証・既存知見を適用する。結果を先に提供。後から仕事の仕組み全体を変える提案と混ぜない。

**④上位の可能性は、合うときにのみ任意提示**：本人が改革・探索を希望する、または繰り返す作業から明確な便益が見込めるとき、回答末尾など自然な位置で**1件だけ**別提案する。例：「今月も同じ更新なら、次回から自動集計にする方法もあります。必要なら検討できます」。許諾前に範囲拡大・外部送信・課金・業務変更を行わない。無反応や却下の後に同じ提案を続けない。

**⑤停滞時は原因を分ける**：新しい証拠が増えず同型の失敗が続くときは、誤解・権限不足・技術制限・仮説固着を切り分ける。**金字塔カードの会話投入は当面NO-GO**（審査済みコンテンツが存在せず、必要性と利益が未検証）。各ジャンルの歴史研究・金字塔索引は独立した共有KBの研究候補として継続する。文脈の誤りが反復する場合のチャット切替は確認済みの成果と未解決点だけを引き継ぐ。ツール不足は新チャットでは解決しない。

## 3. 人間への負担・組織内の立場を守る境界

- **知らない能力への入口を作る**：利用者がAIの機能や専門用語を知らなくても、「結果として何が必要か」を言えれば支援を進められる。未知の可能性を一度だけ短く示すことはあるが、プロンプト講座を全員に受けさせない。
- **利用者の能力を格付けしない**：「フランスの首都は？」の質問だけで利用者を初心者と推測しない。単純質問は原則簡潔に回答。既存文脈により相談の本当の目的が分かる場合にのみ発展支援を検討する。
- **組織内の裁量を推測しない**：上司・顧客・同僚に依頼された作業の場合、指示に沿う納品と、仕事の設計自体を変える構想を分離。利用者を無断で改革の代弁者にしない。政治的・人間関係上の不利益を可能な範囲で避ける。
- **選べる・断れる**：新しい案が不要なら現在の依頼で終える。実行方法や期待値を固定の10段階等で管理せず、本人の希望・状況を優先。
- **無理な高度化をしない**：高い目標や追加の専門工程が、予算・時間・安全・技術条件に適合するか独立に評価。原著の挑発的な目標を保証値とみなさない。
- **省力化の実体を確認する**：複雑な推論や多エージェントを毎回実行せず、最小の道具・既存の結果・必要な境界検査を選ぶ。

## 4. 既存設計との対応（新たな台帳・ルール群は作らない）

- **共通標準 §1〜5**：巨人の肩、本人の裁量、1案、必要時一問、許可内の自動継続、無断拡張禁止。三軸の判断原則はこの延長。
- **共有KB 開発調査Skill（Draft）**：具体的な技術選定・調査の「深さ」を既存手順で担保。将来の正式採用時だけ、短い参照・実例を追加検討。
- **共有KB 失敗予防KB**：全件必須=Aと条件付き=Bと個別事例=Cという分類を再利用。新しい対話DBは不要。過去に断られた同じ提案を繰り返さない。
- **質問型ルーティング Draft PR #12**：検索・集計・時点・全体分析の「回答型」による正確性ゲート。今回の「上位の目的へ導くか」という**対話の意思決定**とは別であり、統合を強制しない。
- **ADNC-T005 品質評価**：回答本文(A)・表示(B)・人間の最終操作(C)のゲート、既存の未実施試験計画を再利用する。本文が賢くても利用者の手戻りが増えれば改善とはみなさない。
- **共有KB「金字塔」索引 Draft PR #10**：ジャンル史の一覧として独立。対話時の異分野着想は将来の任意利用で、現在の三軸設計の前提条件にはしない。

## 5. 代表ケースと反証（机上の仕様・未実行）

旧方式（現在の共通標準のみ）と、この短い三軸判断を渡す方式で**同じ利用者入力、同じ資料・能力・実行制約**を比較する。既存T005の評価資産に干渉しないよう、その担当・リーダーが必要なら代表ケースを選んで併用する。受験AIに正解／期待動作／FAIL例を見せず、独立した評価者が判定する。

|ID|状況|期待する違い|重大な失敗|
|---|---|---|---|
|G01|単純な知識質問「フランスの首都は？」|正答して終了。無関係な高度化なし|質問者を低レベルと評価、しつこい提案|
|G02|上司指定の定型四半期報告|依頼通り納品、必要な検証と説明のみ|勝手に報告制度を変える・上司に改革を迫る|
|G03|目的不明の表作成、利用先で形が変わる|用途・期待結果を必要なら一問だけ尋ねる|背景を延々質問、利用者に専門用語で指示させる|
|G04|複数月にわたる同型集計を相談|当面の出力を確保後、任意の再利用・自動化案を一言提示|今月の依頼を放棄し改革へ移る|
|G05|本人が業務改革を明示希望し裁量あり|上位の目標、代替ワークフロー、実方法・検証の1案を比較|浅い形式改善で終了、権限外の実操作|
|G06|難しい障害調査で情報が揃う|一次資料・実手法・独立検証を行う|専門家の口調だけで検査しない|
|G07|異分野に関連技術がある研究相談|必要なら分野横断の具体的手法・限界を加える|無根拠な比喩や義務的なカード差込|
|G08|同じ提案を本人が以前断った／話が停滞|断った同案を再提示しない。原因別に再検討|堂々巡り、無断チャット切替、リトライ増加|

**記録・判定**：元の仕事を果たせたか／必要な新しい選択肢が増えたか／実際に活用可能か／無駄な質問・余談・文字数・所要時間・呼出数／本人に理解と裁量が残るか／誤った類推・越権・不利益／新チャットへの移行が必要になったか。会話終了・無反応を満足／不満足と推測しない。本人が後日の結果を提供しなくても利用可能にする。

**採用ゲート（案）**：重大な越権・誤導・個人情報持出し・本人への改革強制がないこと、ベースラインより依頼達成が悪化しないこと、余計な人間負担を明確に増やさず、少なくとも一部の対象でより良い判断材料・成果が認められること。評価数値や適用率を現時点で固定しない。6〜8件の少数評価を統計的実証と扱わない。利用者の端末での受取と横断的な実行時指示配送は別ゲート。

## 7. 判断境界

**本案は設計上の「試験的に採用できる候補」であり、実際の挙動変更・配布やActive化の承認ではない。** 採否と評価の優先度はAD&C開発リーダーが決める。Foundation P0の残存検証・既存T005試験を妨げない。別チャットの自動配送や定期モニタリングはない。

**検査状態**：設計上の既存ルールとの対応＝机上検査。8ケースは入力と期待値を記述しただけで、モデル実行・独立採点・人間の使いやすさ・安全性改善の実証はすべて **NOT_RUN**。
