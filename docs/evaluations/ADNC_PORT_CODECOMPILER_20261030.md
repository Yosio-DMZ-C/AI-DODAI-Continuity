## 2. 提案する仮説（実証と分離）

**H1：工程・実行・人間ガイドの単一情報源**
- 対策：あらゆるPythonを日本語へ翻訳するのではなく、許可済み操作の型付き・宣言的な工程定義と実装レジストリを作る。同じ工程IDを、日本語Guide・実行プラン・結果JSONへ展開する。
- 期待：別々に保守した手順書とコードの工程抜け・順番のズレが減る。
- 留保：工程名と実行関数の意味的一致は自動では保証されない。規範例／失敗注入／実結果の検証が必要。

**H2：最高効果の候補を最初に小実験**
- 方式選定：UI手作業、AIによる生成、ファイル/定義編集、API/CLI/ALMを事前に短く比較。人間の操作往復を大きく減らせる有望候補を、可逆な架空データで最初に実証する。
- 失敗時：同じ試行を繰り返さず、差のある仮説なら試す。情報が増えなくなれば人間に手作業への変更を提案。固定回数のために有望実験を止めない。
- 留保：現PoCで生産性や人間の操作削減率は未測定。

**H3：安全な操作を束ねた一括検収**
- 条件：実書込先なし、原本不変、権限と範囲を確認済み、各工程が証跡を残す。人間の工程ごとのOKを不要にし、最後に検査結果と元データ不変を報告する。
- 留保：破壊的操作・外部送信・公開・課金・本人採否・回復不能なデータ更新を自動で一括承認する提案ではない。

## 3. コード分野の最小PoC（この回に実施）

**実物：** [ADNC_workflow_poc_v0.py](https://github.com/Yosio-DMZ-C/AI-DODAI-Continuity/blob/docs/runtime-quality-pilot-20261016/docs/evaluations/prototypes/ADNC_workflow_poc_v0.py)（Python 3.9+、標準ライブラリのみ／外部通信なし）。

構成：
- `PLAN`：順序付けた工程ID・操作名・相対パス引数
- `OPS`：許可された操作と人間向け説明、実行関数の対応表
- `guide(PLAN)`：日本語の工程リスト（総数・工程ID・説明）を自動生成
- `run(root, PLAN)`：安全な隔離フォルダで実行し、同じ工程IDとPASS/FAILをJSONで返す
- `selftest()`：通常動作・不正入力・未許可操作・危険パスの4ケース

実施した実験（実行実績の範囲）：
1. 架空入力JSONの読込・保全 → 別名出力 → 原本・期待差分検証：**3/3工程PASS**
2. ガイド上の工程ID [S1,S2,S3] と実行PLANの対応：**PASS**
3. 壊れたJSONを投入した場合に失敗表示を保持：**PASS**
4. 未許可操作 `delete` と `../secret` パスを実行前に拒否：**PASS**

ローカル `python ADNC_workflow_poc_v0.py` の実結果：**selftest 4/4 PASS**、通常例の最終status=PASS / completed=3 / total=3。GitHub上のコードは書込後のUTF-8全文読戻し・提出本文一致を検査した。

**できていないこと**：
- このPoCはPythonの汎用的な自然言語コンパイラではない。デモ用操作は限定3種類で、フローUIの外部操作や画像は含まない。
- Guideの表記と関数内部の意味一致、実OS差異、例外時の永続復旧、機密管理、本番承認の保証はしない。
- 人間の3工程以上の操作UI、実SharePoint／Power Automateへのインポート、コード領域の対象別適合性は未検証。
- GitHub公開先コードの**別環境での再実行**はNOT_RUN。ローカルで行った静的／実行検査と分ける。

## 4. 次の効率的な実験（既存T005に追加、別タスク不要）

まず1組だけ：**架空の定義JSONを書き換える作業**を対象に、A=AIがUIクリック手順を逐次説明する案、B=宣言型PLANからガイド・実行・検収が一体生成される案を、同じ入力と成功条件で比較する。実画面の手操作が不要なら、それぞれの必要操作数を見積もるだけでなく、実際の操作・手戻りを記録できる時だけ測定する。

共通PASS条件：
- 既存原本が不変、意図した差分だけ別名で作成、形式・参照整合を検査できた
- 人間がどこから始めて、いつ画面を見ればいいかを判断できる
- 失敗時に重複更新しない／失敗をPASSに見せない
- 人間操作の総数、再指示回数、予期せぬ承認、処理失敗を別々に記録
- Q1記述、Q2独立解釈、Q3実行、Q4用途への合致を分離（Q3は隔離環境と本番環境を分離）
- 既存T005の固定分母（4件スモーク・20件・新40件）、UI-A/B/C と完走条件A/B/C を上書きしない。新PoCは研究上の**追加観測**。

**止め方：** 新しい知見のない同一UI反復、保存・安全性エラー、実データ危険が出れば当該方法を再評価／停止。軽微な局所ミスなら検査後の可逆な修正を許す。切替判断に合理的な余地があるときだけ本人に手作業案を相談する。
