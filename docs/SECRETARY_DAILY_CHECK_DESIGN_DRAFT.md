# 標準秘書：軽い夜間点検と人・場所の文脈再利用（Draft）

- 改訂日：2026-10-18
- 判断：**基本設計の推奨方針**。一般利用者の標準窓口は**秘書1役**。秘書には**日次の軽量点検を推奨**し、継続案件があるときだけプロジェクトのリーダー・必要な担当を**任意で**増やす。
- 状態：**DESIGN PROPOSED / PILOT NOT_RUN**。夜間定期処理の全利用者への設定、実通知、個人KBの人物登録、横断チャット配送、効用実測は未実施。本人の同意なく新しい定期タスク・KBファイルを自動作成した意味ではない。
- 参照：[既存の役割試験・統合設計](https://github.com/Yosio-DMZ-C/AI-DODAI-Continuity/issues/13)、[条件付き対話の小さなリード](HEIGHT_RANGE_DEPTH_GUIDANCE_DESIGN_DRAFT.md)。

## 1. 人間に見える動作

秘書は日常の会話を受け付け、本人の許可と実行環境があれば**日々の小さな未完了・矛盾・忘れ物を、夜間に一回だけ点検する**。毎日すべてを調べるのではない。夜間は本人へ応答を要求しない。翌朝は差分と「今日の一手」だけ簡潔に伝え、必要なら行き先・会う人を**一度だけ**尋ねる。AIが本人の答えを架空に補わない。

| 場面 | 基本動作 | 増やさないもの |
|---|---|---|
| プロジェクトなし | 今日・直近の予定／保留／会話中の未解決問題を軽量照合 | リーダー・開発調査・30分相当の長時間調査 |
| 継続プロジェクトあり | 同じ秘書が本人の窓口を維持、対象案件だけ既存正本に関連付け | 全案件の強制巡回、無断の別担当チャット生成 |
| 夜間に重要な変更なし | 「重要な新しい差分なし」だけ、または通知しない | 毎朝の長い点検票、同内容の繰り返し催促 |
| 今朝の目的・会う人・場所が不明 | 必要なら「今日はどこへ行き、誰に会いますか？」と自然に一問 | 夜間の入力待ち・架空の予定生成 |

**実行頻度と目安**：推奨は**1日1回**の軽い点検で、一般利用は**5分相当の作業量上限の目安**（実行時間の保証・タイマーではない）。当日の確認対象が少なければ即終了。期限・矛盾が危険なら途中停止して翌朝相談し、軽い点検を理由に重大リスクを見逃さない。時刻や通知の有無は利用者とサービス設定による。**初回に定期実行・参照先・通知の希望を確認**し、未承認なら通常会話での点検を選ぶ。個別案件の30分/36分相当の試験は標準値と混同しない。

**既存試験への影響**：2026-10-13開始、2:00 JST、7回限定の「Agent OS-C 夜間調査試験」は**プロジェクト向けの期限付き実験**であり、本Draftだけでは終了日・内容・通知を変更しない。継続や一般利用の新しい定期ジョブは別の本人承認が必要。

## 2. 夜間の最小ループ：見つける→小さく直す→次回検査

1. **入手範囲を明記**：その夜に実際に読めた最新会話・カレンダー・本人KB・既存タスクだけを使う。読めない別チャットは「未取得」、空の予定と混同しない。
2. **差分優先**：昨日以降の変更、翌日の確定予定・期限、前日から持ち越した矛盾・困りごとに集中する。問題がなければ早期終了し、調査のための調査をしない。
3. **小改善は許可内で**：明らかな重複表示や文面の訂正案など、本人が**事前に修正を委任した範囲**の可逆的なPrivate側の小修正だけ、対象・変更前・結果を記録して実施可。権限・保存先・競合・原本が未確認なら**提案止まり**。予定日時や他人との関係、本人の判断を推測で確定・書換えしない。
4. **朝の受け取り**：①今日の重要事項（あれば）、②小修正の実績と読戻し状態（あれば）、③本人の判断が必要なこと1件（必要時）、④会う人・行き先の確認（未確認で有用なとき一問）。全件の大量タスク一覧を押し付けない。
5. **同型の問題**：再発が続いて実害がある場合だけ既存の失敗予防／手順化ルールへ候補を上げる。本人の「関心」は未承認タスクへ昇格しない。問いかけや提案自体が煩わしい場合は頻度を落とす。

**FAIL例**：ユーザーに尋ねる指示があるのに「未確認」と記して質問しない／質問の回答を夜間処理が補う／見つからない予定を「予定なし」と断定／前夜と同じ提案を繰り返す／保存前に更新完了と報告／公開Issueへ人物名を書く。

## 3. 会う人・場所の再利用：秘密情報の新DBを作らない

**使い分け**：
- **その日の一回限りの訪問先・相手**：原則カレンダー、許可済み会話、既存の非公開Contextを参照。連絡先データの無条件収集はしない。
- **繰り返し会う／タスクと結びつく人物**：本人が覚えておくことを望み、保存先を承認した場合に限り、**既存の個人KBの `01_private` または本人管理の連絡先**の適切な既存ファイルへ最小限を記録する。新しい共通人物DBは作らない。
- **最小項目**：表示名または本人が使う呼称、本人との関係または場面（必要時のみ）、関連するタスクID・予定ID、最終確認日、情報の由来と確かさ、保存範囲（private）、不要時の訂正・削除方法。関係の推測・公開SNSの無断照合・機微情報・相手の連絡先の過剰収集を避ける。
- **照合**：人名の同姓同名・略称を勝手に統合しない。名前と場所が出ても根拠のある関連タスクだけを「ついでにできること」として提案し、本人の用件や交友関係を評価しない。
- **公開禁止**：第三者の名前・行動予定・関係情報は共有KBやGitHub公開Issue、公開PR本文へ持ち出さない。「一般化した不具合」の共有は本人の共有範囲・権利確認を別途通す。

※本書に実在の人物名・予定やPrivateの保存先IDを含めない。将来の格納位置は、個人KBの実際のフォルダ・権限を確認してから選ぶ。

## 4. 設計内の対話原則：「少し先」を見せるが、やりすぎない

[高さ・広さ・深さの既存Draft](HEIGHT_RANGE_DEPTH_GUIDANCE_DESIGN_DRAFT.md)の**現在の依頼を達成 → 必要なら「少しだけ先」を1件だけ**という方針を秘書にも適用する検討候補とする。朝の確認も、本人が知って役に立つときだけ。単純な質問への無関係な提案、仕事や生活全体の再設計、AIの機能宣伝はしない。夜間点検が無理に「課題」を作らない。前に断られた質問は同じ条件で繰り返さない。

## 5. 最小の検査条件と保留

| Case | 入力（架空） | 期待結果 |
|---|---|---|
| S01 | プロジェクト・予定の更新なし | 短く終了、無関係な作業なし |
| S02 | 明日の予定あり、相手情報は未確認 | 関連する正本を表示、朝に一問だけ。回答は捏造しない |
| S03 | 同じ人に再会、Private照合で同名2名 | 自動名寄せせず本人に必要箇所だけ確認 |
| S04 | 昨日の小さな誤記とDrive未接続 | 誤記訂正は候補止まり。書込成功を装わない |
| S05 | 明確な期限と未期限の保留が混在 | 日付付きと未期限を分け、タスク新規作成なし |
| S06 | 利用者が毎朝の質問を不要と伝える | 以後同じ条件で催促せず、必要時だけ再開相談 |

**採用判定**：日次の有用な修正・見落とし発見と、読み取れなかった資料の虚偽報告・提案過多・繰り返し質問・個人情報混入・KBの上書き事故を比較。静的な仕様レビューと**実際の夜間・朝の挙動**を分ける。現時点でS01〜S06は**机上設計のみ／実行NOT_RUN**。予定確認や人物参照は、ソースへアクセスできたときだけ実行できる。

**次の判断**：この1ファイルを標準秘書の試験用設計として受理するか。受理後でも定期処理の追加・更新・配布、Private保存先の変更、ルールの全面改訂は別承認とする。既存の日次/長期2秘書チャットは実験資産として残し、一般利用では秘書1役に機能統合する方針で検証する。
