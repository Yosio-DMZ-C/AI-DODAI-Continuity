# AgentOS-C

**AgentOS-C** は、バラバラに存在するAI機能・記憶・資料・手順・作業状態を、**普通の人が継続利用できる1つの運用単位へまとめる**ための個人向けAI運用基盤です。

> AIごとに自分を覚えさせるのではなく、自分のAgentOS-CへAIを接続する。

AgentOS-Cは新しいLLMや新しいアルゴリズムではありません。Memory、RAG、クラウドストレージ、エージェント、検索、手順書など、すでにある部品を**導入しやすく、再現しやすく、引き継ぎやすい形へ束ねる「簡易インストーラー＋運用モデル」**です。

目指すのは、誰にとっても理論上最高のAI環境ではなく、まず多くの人にとって普通に動く**最大公約数のパッケージ**です。

## まず3ステップ

1. 自分の環境に合う設計書をAIへ添付する
2. チャットで `実行` と送る
3. AIの推奨案を確認し、問題なければ `進めて` と送る

保存先の選択、接続確認、初期構成、実ファイル生成までAIが案内します。

短い手順だけ見たい場合は [QUICKSTART.md](QUICKSTART.md) を参照してください。

## どの設計書を使うか

判断基準は**料金プランではなく、そのAIが保存先へ直接読み書きできるか**です。

### クラウド等へ直接読み書きできる

[AgentOS-C 設計・構築運用指示書 — 一般配布版](docs/AgentOS-C_設計・構築運用指示書_一般配布版.md)

AgentOS-Cを展開Workspaceとして保存し、必要なファイルだけを差分更新します。**現時点の実績は接続済みGoogle Drive**です。Notionなども接続先の候補ですが、AIからの読み書きとAgentOS-Cの構造維持を確認した場合のみ採用します。**有料プランでも利用できる接続機能は一律ではありません。**

### 直接読み書きできない / ファイル添付中心

[AgentOS-C 設計・構築運用指示書 — AI無課金ユーザー版](docs/AgentOS-C_設計・構築運用指示書_AI無課金ユーザー版.md)

こちらは**「KBの構築＋外部バックアップ」を基本機能**とします。本人から提供された文書・情報をAIが整理し、可能ならZIP、ZIP生成が使えなければ全文とファイルの相対パスを含む単一Markdown/TXTとして渡し、利用者自身が保存します。

**継続更新、別チャットからの読み戻し、Grok等の別AIからChatGPT無料版への移植、OneDrive等との直接同期は基本機能として保証しません。** 実際に読込・再生成できる環境だけで個別に検証する拡張機能です。AIの料金区分だけで動作を判断しません。

[動作環境・実証済み／未検証の一覧](docs/COMPATIBILITY_STATUS.md)

[ChatGPT Freeの公式ファイル対応・上限](https://help.openai.com/ja-jp/articles/8555545-uploading-files-and-audio-to-chatgpt) / [データ分析の対応形式](https://help.openai.com/ja-jp/articles/8437071-data-analysis-with-chatgpt)：無料版にもファイル入力機能はありますが、利用量の制限があります。**ZIPの生成・取込とダウンロードは別途実機検証が必要**であり、本プロジェクトが保証するものではありません。

開発調査や成果物作成の共通定石と進行スタイルは、[開発調査・止めないプロジェクト推進の共通標準](docs/PROJECT_EXECUTION_STANDARD.md)を参照してください。利用者の確認待ちを減らしつつ、未承認の外部操作は行わない設計です。

## AgentOS-Cで解決したいこと

今のAIには、LLM、Memory、RAG、MCP、Cloud、Agents、Search、Automationなど、多くの部品があります。

一方で、長期運用すると次のような問題が残ります。

- チャット履歴、メール、資料、手順、メモリが分断される
- AIを変えるたびに前提や判断を説明し直す
- 「調べた」「欲しい」「注文した」「持っている」が混同される
- 長い作業で、完了済み・未実行・失敗・再開位置が失われる
- 訂正や成功・失敗が、その場の回答だけで終わる

AgentOS-Cでは、知識・判断・手順・作業状態をAIサービスの外側へ残し、AIが変わっても同じ正本を使えるようにします。

## 共有知：主要な議論を調べる時間を短縮する

共有知の焦点は、主要な主張・支持根拠・反論・未解決点・専門家の公開見解を比較できるようにすることです。答えや勝者を必ず提示することは求めません。個人差と科学的知識の更新を前提に、本人が選べる材料を整えます。

[AgentOS-C Shared Knowledge](https://github.com/Yosio-DMZ-C/AgentOS-C-Shared-Knowledge) で、主張比較資料と行動推奨を含む手順書を区別し、掲載と推奨の審査を分離します。共有知の独自文章等はCC BY-SA 4.0、本体の既存MITライセンスは維持します。現在は基本設計段階で、具体的な比較資料は次工程で制作します。

## プリインストールSkill：Core Life Skills（設計追加）

AIの利用者は、問題が起きてから膨大な情報を一から調べる余裕がないことがあります。子育て、健康・医療、メンタルヘルス、投資・住宅購入、災害、契約、デジタル安全などの高難度な場面では、**初動・確認・記録・専門家への相談準備**を助けるSkillを標準提供することを目指します。

構成は **Core（標準知）→ Community（出典と比較の品質を確認した共有知）→ Personal（本人の条件に適合させた知識と手順）** の3層です。

将来的には、研究・複数の独立した専門的見解を根拠の質で整理し、個人の条件に照合して、適切な専門領域や確認済み専門家の候補を提示する仕組みを目指します。**集合知は多数決ではありません。** 専門家への連絡や個人情報の提供は本人の承認を前提とします。

**現時点では設計・ロードマップ段階**です。完成済みの診断、専門家マッチング、相談予約サービスではありません。初回インストールを重くしないよう、基本INDEXと必要時に取得する領域別Skillを想定しています。

困っている人が意思決定に疲れている場合は、初回から**専門家／専門領域の第一候補1件、なぜその状況に合うか、未確認点、今行う1操作**を短く示す設計です（実在候補は確認できた場合のみ）。防災は、家族の連絡・備え・避難情報・アウトドア用品の安全な転用を扱う軽量Skillから始めます。

## 基本モデル

### KBを正本、AI Memoryをキャッシュにする

長い詳細、根拠、履歴は外部Knowledge Baseへ置きます。

AI Memoryを利用できる環境では、よく使う条件や入口を引く短い索引として使えます。**MemoryがないAI環境でもKB本体を構築・バックアップできる設計**とします。

- KB = 正本 / SSD
- AI Memory = 高速キャッシュ

モデルやサービスを変更しても、正本は残ります。

### 作業状態も残す

`BUILD_PLAN.md` に、完了済み・未完了・失敗・未検索・次の再開位置を残します。

これにより、別のAIや別セッションでも「前の続きやって」から再開できることを目指します。

### AIに勝手に意味を膨らませさせない

本人発言、一次資料、AI提案、推論、未確認を分けます。

たとえば、

`調べた → 欲しい → 注文 → 配送完了 → 所有報告 → 棚卸し`

は別の状態として扱います。

注文記録だけで現在庫を増やしたり、AIの提案を本人の決定へ変えたりしません。

## AgentOS-Cの基本構造

```text
AgentOS-C/
├─ START_HERE.md      # AIが最初に読む入口
├─ BUILD_PLAN.md      # 現在の作業状態・再開位置
├─ 00_system/         # 設計・台帳・ルール
├─ 01_private/        # 個人情報・私的記録
├─ 10_sources/        # 原文・根拠
├─ 20_knowledge/      # 整理済み知識
├─ 30_contexts/       # 再開・用途別の入口
├─ 40_outputs/        # 派生成果物
├─ 50_skills/         # 再利用するAI作業手順
├─ 60_memory_backup/  # AI Memory等のバックアップ
├─ 70_scripts/        # 検査・補助スクリプト
├─ 80_reviews/        # 品質確認・レビュー
├─ 85_attachments/    # 大容量原本
├─ 90_history/        # 旧版・履歴
└─ 99_inbox/          # 未分類
```

初回からすべて作る必要はありません。必要な部分だけを使い、用途に応じて増やします。

## 知識のライフサイクル

AgentOS-Cは単なるフォルダ整理ではなく、次のサイクルをAIに回させることを狙います。

```text
Raw Source
   ↓
Evidence
   ↓
Knowledge
   ↓
Context / Skill
   ↓
AIが利用
   ↓
訂正・追加
   ↓
差分更新
   ↓
History / Review
```

使うほど、正本・Context・Skillが改善されていく構造です。

## このGitHubに入れないもの

このリポジトリは**AgentOS-Cの一般公開用仕様・説明・テンプレート**を置く場所です。

次のものはコミットしません。

- 実際の個人KB
- 個人のチャット履歴
- 購入履歴・健康情報・仕事情報
- 非公開URLやファイルID
- APIキー、秘密鍵、認証情報
- 個人用Memory Backup

実際の個人KBはPC・スマホ内のファイル、Google Drive、個人用OneDrive等の**非公開の永続保存先**で管理してください。**保存先に人間がファイルを置けることは、AIが直接読書きできる証拠ではありません。**

## Release package

`release/` には配布パッケージのREADMEとmanifestを置いています。

ZIPは搬送・初回導入・バックアップ・スナップショット用の形で、日常運用の正本は利用モードによって異なります。

- 構築・バックアップモード：外部保存した**最後に検査済みの完全版**ZIPまたは互換単一Markdown/TXTを保有する（後日更新できるとは限らない）
- 直接読書きモード：展開Workspaceが正本、ZIPはスナップショット
- 任意の手動更新モード：既存KBの入力と完全版成果物の出力がそのAI環境で可能だと検証済みの場合だけ、完全版を再生成する

ZIPと展開Workspaceを別々に編集して、正本を二重化しないことが重要です。
