# AD&C — AI-DODAI & Continuity

> **AIを替えても、冒険は続く。**

**AD&C（旧名称：AgentOS-C）**は、**既存のAIをオペレーターとして、知識・判断・作業状態を自分が管理するファイルに残して活用するための「対話型インストーラー＋運用の型」**です。新しいLLMやエージェント実行環境を作るものではありません。

**AI-DODAI**の「DODAI」は日本語の「土台」。知識・判断履歴・作業状態を人間の管理するファイルに置き、各AIが共通ルールと記録を読みながら、その推論能力を使って進めるという考え方です。TRPGのルールブックと冒険の記録をGMが引き継ぐ、という比喩で説明できます。ただし、AIをまたぐ継続動作は現在も検証中です。

**名称変更済み（2026-10-14）：** 本体リポジトリは [AI-DODAI-Continuity](https://github.com/Yosio-DMZ-C/AI-DODAI-Continuity) に改名しました（旧名：AgentOS-C）。配布タグ `guides-current` と既存の配布ファイル名は維持しています。旧URLからの実ダウンロードとファイルの独立ハッシュ照合は未検証です。[移行計画と検査状況](docs/ADNC_NAME_MIGRATION_PLAN.md)を参照してください。

入口はシンプルです。設計書を使い慣れたAIへ渡し、`実行` → `進めて` で、自分の知識ベース（KB）の構築を試せます。Markdown等の既存技術を使い、利用者が最初から専用システムを設計・実装する負担を減らします。ただし、ファイル作成・外部保存・次回再開に使える操作はAI環境により異なります。

## AD&Cの基本理念

> **どんな玄人も、専門外では素人だ。**
>
> **玄人の「当たり前」はAIが案内。人間は、その先の判断に集中する。**

**人間の判断をAIに置き換えるのではない。人間が判断すべきことを、もっと上質にする。** 各分野の基礎知識、標準手順、判断基準を出典や適用条件とともに共有することを目指します。AIが基本の確認事項を案内し、利用者は目的・価値観・最終選択を担います。「誰もが玄人になれる」という意味ではありません。共有知の正式Active項目はまだ0件で、現時点の効果は検証中です。詳しくは[設計・構築運用指示書](docs/AgentOS-C_設計・構築運用指示書_一般配布版.md)を参照してください。

## 何のためのインストーラー？

**As-Is：** 知識やアイデアがあっても、AIごとに前提が散らばり、調査の再実施やITの設定・連携に時間を取られる。

**To-Be：** 専門家も一般の利用者も、本人が考えるべき課題に集中する。AIが参照資料・作業手順・判断理由を扱えるようにし、知識の引き継ぎと再利用を容易にする。

**長期目標は、より良い人生の選択を支えること。** 医師・研究者・教育者などが、ITの利用障壁に足止めされず、自分の知見を実務や共有知に生かせるなら、社会全体の知的生産にもつながるはずです。これは目指す効果であり、実証済みの生産性向上ではありません。

## まず試す：3ステップ

1. [導入ガイド](docs/wiki/Getting-Started.md)を開き、自分の環境に合う設計書をダウンロードして、AIのチャットにアップロードしてください。 [操作が分からない場合（端末別の動画）](docs/wiki/Upload-File.md)
2. チャットで `実行` と送り、AIが示す保存先と作成案を確認する。
3. `進めて` と送る。作成された知識ベース（KB）を受け取り、自分の保存先に保管する。

[**はじめての方へ**](docs/wiki/Home.md) ／ [**Quick Start**](QUICKSTART.md)


## 検証に協力してくださる方へ（任意）

AD&Cを初めて使う方に、**インストーラーの `実行` → 保存先選択 → `進めて` → KB作成**を試していただくための追加手順を公開しています。通常の導入に追加検証は必要ありません。

- **[① 初めての方向け・構築と検証ガイド（Draft）](docs/volunteer-testing/ADC_FirstTime_Test_Guide_v0.1_DRAFT.md)**：初回操作と、実際にファイルを受け取り開けたかの確認。
- **[② 構築後テスト・レポート生成指示文（Draft）](docs/volunteer-testing/ADC_PostInstall_Test_Prompt_v0.1_DRAFT.md)**：構築した**同じチャット**でAIへ渡し、確認できた範囲の検査結果をMarkdownにまとめます。

**ZIP形式の検証キットを取得する必要はありません。** 各MarkdownをGitHubから個別に保存・添付して使えます。検証できなかった箇所も有用な結果です。個人KB、チャット全文、実名や非公開URLは公開しないでください。共有する場合は、本人が確認した匿名化済みの結果だけを任意に提供してください。


## どんなことができる？

- **知識の引き継ぎ：** 資料や判断の経緯をまとめ、説明のやり直しを減らす。
- **作業の再開：** 完了した作業と未完了の作業を残し、続きから取り組みやすくする。
- **ファイルの管理：** AIのチャットだけに依存せず、PCやクラウドで知識を保管する。

**現在、限定的に確認できているのはKBの初期構築と外部への保存・読戻しです。** 別チャットでの再開には成功例もありますが、安全な継続更新やAI間移植の再現性は検証中です。成果物ごとの成功・失敗・未実施を分けて記録しています。

## 自分のAIに合う導入方法

**クラウドへの直接読み書きを確認できたら：** [一般配布版](docs/AgentOS-C_設計・構築運用指示書_一般配布版.md)で、保存先にKBのファイルを作成します。

**添付ファイル中心、または接続可否が不明なら：** [AI無課金ユーザー版](docs/AgentOS-C_設計・構築運用指示書_AI無課金ユーザー版.md)で、ZIPなどを受け取り、自分で保存します。

設計書はAIへの作業指示を含むMarkdownファイルです。「AI無課金ユーザー版」は、無料プラン専用という意味ではありません。

[実動作の検証結果](docs/wiki/Verified-Results.md)では、Claude・Gemini・Grokなどで試した内容を紹介しています。利用できる機能はAIサービスや接続環境によって異なります。

## 中身は普通のファイル

AD&Cでは、主に次のようなファイルを使います。

| ファイル・フォルダ | 役割 |
|---|---|
| `START_HERE.md` | AIが最初に読む、KBの入口 |
| `BUILD_PLAN.md` | 作業の進行状況と次の手順 |
| `00_system/registry.json` | ファイルや記録を探すための管理情報 |
| `20_knowledge/`・`30_contexts/` | 整理した知識と用途別の引き継ぎ情報 |

最初からすべてのフォルダを用意する必要はありません。必要な範囲から始められます。

## 開発調査から始め、知識の共有へ広げる

**先行利用できる例（Draft）：** [開発調査・技術選定Skill v0.1.0-preview](https://github.com/Yosio-DMZ-C/AgentOS-C-Shared-Knowledge/blob/main/skills/development-research/SKILL.md)。課題の整理 → 公式仕様の確認 → 現実的な1案 → 未知の操作だけ検証 → 判断理由の記録、という手順をAIへ渡せます。限定的な接続検証例がありますが、**正式Active版ではなく、省力化の効果も未計測**です。

この先は、以下を検証・整備する構想です。

- **組織標準KB：** 会社や団体の正式な規程・社内文書・手順を、業務時に一般的な情報より優先して参照する。
- **インストーラKB：** 組織の既存資料を、根拠と例外を残したまま使いやすいKBへ導入する。
- **共有知：** 主張・根拠・反論・未解決点を比較し、専門知を他の人も再利用できる形にする。
- **Core Life Skills・専門家への接続：** 子育て、医療、契約、防災など、重要な場面の初動や相談準備を助ける。

共有知の正式なActive項目は現時点で0件です。**構想と実装済み機能を混同せず、小さな実例から育てます。** [詳しい構想を見る](docs/wiki/Future-Vision.md)
